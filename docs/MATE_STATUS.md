## 三、根因：逃路归因无法区分这些杀法

把 7 个局面的四条逃路逐条试走，结果：

```
白脸将(实测)   受攻 / 受攻 / 照面 / 宫外
白脸将(实战)   照面 / 宫外 / 宫外 / 受攻
双车错         照面 / 宫外 / 受攻 / 宫外
双照将         照面 / 宫外 / 受攻 / 宫外
钓鱼马         照面 / 宫外 / 受攻 / 宫外
侧面虎         照面 / 宫外 / 受攻 / 宫外
卧槽马         照面 / 宫外 / 受攻 / 受攻
挂角马         照面 / 宫外 / 受攻 / 受攻
```

**双车错、双照将、钓鱼马、侧面虎 四条完全相同。**

这说明"将被怎么困死的"这一层信息不足以命名。这几个名字描述的是**进攻方的组合方式**，
不是防守方的死亡方式。用防守方视角反推进攻方组合，信息量不够。

## 四、结论

杀法命名需要"进攻方意图/组合"这一层信息，而终局盘面里这一层往往是**多解的**：

- 同一盘面，可以同时符合"双车错"和"白脸将"的形式
- 真实棋谱里，棋手是按**自己怎么走的**来命名，不是按终局长什么样

所以：**仅凭终局盘面做杀法命名，本质上是一个多解问题，不可能做到准确。**
这不是调参能解决的，是信息不足。

## 五、可选路线

### 路线 A：只用可唯一判定的
只保留判据互斥的：
- 困毙（未将军 + 无子可动）
- 重炮（射线中间唯一子是己方炮）
- 闷宫（射线中间唯一子是对方士且贴将）
- 其余统一显示"将死"

准确率 100%，但只覆盖少数形制。

### 路线 B：引入最后一手信息
用"最后一手是谁、从哪到哪"缩小范围。例如：
- 末手是马且落在 (3,2)/(5,2) → 挂角马
- 末手是车且两车不共线 → 双车错

这能解决大部分冲突，但仍需逐条校准，且用户实战里末手不一定是"命名起决定作用"的那一手。

### 路线 C：需要标注数据
拿至少几十条"局面 + 正确名称"的真实样本，逐条对齐。
这是唯一能达到"用户认可"的方式，因为名称本身是约定俗成的，不是可推导的。
